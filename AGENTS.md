# Правила работы над выпусками

Эти правила обязательны для любых агентов, которые анализируют интервью,
проектируют экранную графику или меняют Remotion-проект.

## Перед началом работы

1. Прочитать `README.md`, `docs/user-checklist.md` и
   `docs/slide-production-guide.md`.
2. Для конкретного выпуска прочитать его `01-decisions.md`, файл вопросов,
   транскрипт и уже принятые визуальные планы.
3. Не считать краткий ответ из файла вопросов точной расшифровкой: сверять его
   с транскриптом и таймкодами.
4. Считать STT-транскрипт навигационным источником, а не основанием для
   монтажных сокращений. Он может ошибаться в словах, говорящих и границах
   реплик.
5. Не менять код слайдов до принятия визуального плана вопроса. План создаётся
   по `templates/question-visual-plan.md`; несколько вопросов можно отдавать
   на ревью одной пачкой.

## Таймкоды и монтажная шкала

- Таймкод пользователя без явной пометки всегда означает `review-time` —
  время, которое показывает `FullInterviewReviewDev` / `FullInterviewReview`
  после монтажных вырезов.
- `video/review-timeline.tsv` хранит `source-time` исходного интервью. Не
  пересчитывать шкалы вручную: использовать из `video/`
  `npm run time -- review-to-source MM:SS` или обратную команду
  `npm run time -- source-to-review HH:MM:SS`.
- После добавления сегмента проверить обе шкалы командой
  `npm run time -- segment SLIDE_ID`.
- Каждый явно принятый пользователем review-интервал добавить в
  `video/review-timing-locks.tsv`. `npm run check` обязан подтвердить lock.
- Тайминг считается проверенным только после boundary-render полной
  композиции: `npm run render:timing -- SLIDE_ID`. Проверяются четыре кадра:
  перед началом, на начале, перед концом и на конце сегмента. Изолированный
  `ReviewSlide` проверяет вёрстку, но не положение в ролике.
- Монтажные вырезы изменяются только в `video/src/editorial-cuts.json`.
  Нельзя дублировать их числа в TypeScript, Node.js или Bash.

## Редакционные ограничения

- Экран не должен пересказывать звучащий ответ предложениями. Он должен
  удерживать сложный контекст, показывать код или связь, дополнять, уточнять
  либо исправлять сказанное.
- Повторять допустимо вопрос, ключевой термин, короткий вывод и код, который
  сейчас обсуждается.
- Один экран содержит один смысловой слой. Новый экран появляется на
  смысловом переходе речи, а не ради декоративной динамики.
- Не добавлять мета-подписи вроде «Дополнение редакции», «Главная мысль» или
  «PHP-вопрос собеседования», если без них понятен смысл элемента.
- Маркировать только то, где зрителю важно происхождение материала:
  существенное исправление ответа или доснятый комментарий.
- Повреждение, восстановление или переозвучку звука не отражать на учебных
  слайдах. Это отдельная задача аудиопроизводства; вопрос оформляется обычной
  карточкой без технических уведомлений для зрителя.
- Не придумывать факты. Технические дополнения и исправления проверять по
  первичным источникам. Спорные формулировки выносить на ревью.
- В плане явно перечислять, что сказано, что добавлено, что исправлено и что
  намеренно не попало на экран. Нельзя молча терять уже принятый контент.
- Не предлагать вырезать, заменять или переставлять фрагменты исходного
  интервью по STT. Визуальный план покрывает исходный разговор непрерывно;
  решения о сокращениях принимает монтажёр после просмотра и прослушивания
  оригинала.
- Не планировать досъёмки или синтетическое восстановление ответа в рамках
  визуального плана. Если кандидат ошибся или недосказал, сохранить исходную реплику и показать
  короткое проверенное исправление на слайде. Не добавлять служебные бейджи
  `Уточнение ответа` или `Исправление`: назначение экрана должно читаться из
  заголовка и содержания.
- Не заполнять паузу информацией автоматически. Дополнительный экран нужен
  только тогда, когда он повышает полезность и не конкурирует с новой важной
  репликой.

## Визуальные ограничения

- Использовать общую сетку и существующие компоненты. Не строить независимые
  сетки для соседних рядов одного экрана.
- Связанные карточки должны совпадать по краям; парные элементы — иметь
  одинаковые размеры, отступы и визуальный вес.
- Не добавлять рамку вокруг всей сцены. Рамки допустимы у функциональных
  панелей, кода и карточек.
- Любой декоративный элемент должен иметь функцию. Удалять подписи, бейджи,
  стрелки и иконки, которые не помогают чтению или пониманию.
- Семантика цветов: фиолетовый — бренд или активный акцент; голубой — структура или
  обычный объект; зелёный — допустимое действие; красный — ошибка; жёлтый —
  существенное предупреждение. Не использовать один оттенок для разных
  смыслов на одном экране.
- Для 1080p ориентиры: заголовок 44–48 px, заголовок карточки 28–32 px,
  основной текст 21–24 px, вторичный текст не меньше 18–20 px, код 22–26 px.
- Карточки вопросов, код и инфографика используют полезную площадь кадра без
  нижней панели аватаров. Крупные аватары показываются только на базовом
  разговорном экране, когда содержательного слайда нет.
- 9:16 является отдельной компоновкой, а не уменьшенной или обрезанной 16:9.
  Смысловые элементы остаются слоями и перестраиваются под Shorts.
- Каждый вопрос, подходящий для Shorts, должен быть понятен без предыдущего
  фрагмента полного видео.

## Скорость и порядок работы

- Сначала разметить пачку из 5–10 вопросов: сложность, таймкоды, экранные
  состояния и wireframe. Затем приступать к реализации принятой пачки.
- Простые вопросы проектировать за 10–15 минут, средние за 20–40 минут,
  сложные — не более часа без отдельного решения пользователя.
- Для ревью сначала рендерить отдельные контрольные кадры 16:9 и 9:16.
  Полный dev-рендер делать в 10 fps после принятия пачки; production — в
  30 fps только перед передачей в монтаж.
- Выполнять один согласованный шаг, останавливаться на ревью и коммитить его
  только после явного одобрения пользователя.

## Критерии готовности слайда

- Экран имеет сформулированную пользу и привязан к точному отрезку речи.
- Текст читается в уменьшенном YouTube-плеере на ноутбуке.
- Нет обрезки, переполнения, случайных рамок, мелкого текста и кривых краёв.
- 16:9 и 9:16 проверены отдельными контрольными кадрами.
- Для изменённого тайминга проверены обе шкалы, timing-lock и четыре граничных
  кадра полной review-композиции.
- Цвета не конфликтуют по смыслу.
- На базовом разговорном экране аватар и состояние говорящего соответствуют
  транскрипту; на содержательном слайде аватары отсутствуют.
- Все принятые факты из визуального плана присутствуют либо причина удаления
  зафиксирована.
