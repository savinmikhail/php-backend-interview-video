# Подготовка YouTube-видео к продакшену

Репозиторий хранит редакционные решения, сценарии, таймлайны, ТЗ монтажёру,
публикационные материалы и разбор результатов выпусков канала
[Mikhail Savin | PHP](https://www.youtube.com/@msavin_php).

Тяжёлые исходники, проекты монтажа и финальные рендеры в Git не добавляются.
Ссылки на них фиксируются в `assets.md` конкретного выпуска.

## Структура

- `docs/user-checklist.md` — исходный чеклист автора без примесей.
- `docs/additional-checklist.md` — дополнительные производственные рекомендации.
- `docs/slide-production-guide.md` — обязательные редакционные и визуальные
  правила экранов интервью.
- `templates/` — повторяемые шаблоны будущих выпусков.
- `templates/question-visual-plan.md` — план вопроса с таймкодами и wireframe
  16:9/9:16 до реализации слайда.
- `episodes/<id>-<slug>/` — рабочая папка конкретного выпуска.

## Этапы выпуска

1. Content audit: просмотреть исходник, проверить ответы и отметить дефекты.
2. Editorial lock: решить, что остаётся, вырезается и требует комментария.
3. Scripts & visuals: подготовить тексты, схемы и графические вставки.
4. Rough cut: собрать черновой монтаж.
5. Technical review: проверить смысл и техническую корректность.
6. Final edit: закончить графику, звук, субтитры и переходы.
7. Packaging: обложка, название, описание, главы и публичная страница.
8. QA и публикация.
9. Postmortem через 48 часов, 7 и 28 дней.

## Статусы

В рабочих документах используются четыре статуса:

- `TODO` — ещё не начато;
- `IN PROGRESS` — в работе;
- `REVIEW` — ожидает проверки;
- `DONE` — принято и зафиксировано.

Решения, влияющие на структуру ролика, сначала фиксируются в
`01-decisions.md`. Финальные таймкоды составляются только после утверждения
монтажа.

`episodes/841862-1payment/visual-plans/` и реализованы в Remotion. Полный

анимации и поздние состояния слайдов сохраняются.

```bash
cd video
npm run render:full-review
```

Результат появляется в `renders/841862-full-review.mp4`. Это review-версия:
она нужна для проверки содержания, таймингов и композиции. После фиксации
правок отдельные экраны можно проверить через композиции `ReviewSlide` и
`ReviewSlideShort`. Для выпуска `841862` обе review-сборки исключают `00:00–14:13.02`,
`00:31:30–00:31:51`, `00:35:02–00:35:53`, `00:44:30–00:45:03`,
`00:56:26–00:56:38`, `01:02:35.7–01:17:37.267` и
`01:17:49–01:21:53` исходника; их итоговая длительность — `46:37.413`.

### Remotion Studio

Полный таймлайн также зарегистрирован как единая композиция для интерактивного
отсмотра:

```bash
cd video
npm run studio
```

В Studio открыть `FullInterviewReviewDev` для быстрого предпросмотра в 10 fps
или `FullInterviewReview` для проверки точного 30 fps-таймлайна. Аудиодорожка
исходного интервью готовится автоматически при первом запуске и не попадает в
Git.

Финальная сборка с авторскими вступлением и заключением зарегистрирована
отдельно, чтобы их длительность не сдвигала `review-time` технического интервью:

```bash
cd video
npm run render:final:dev
npm run render:final
```

В Studio это композиции `FinalInterviewDev` и `FinalInterview`.
С учётом монтажных вырезов в интро и подрезанных краёв исходников длительность
production-композиции — `47:45.63`, при
этом начало первого вопроса остаётся на нулевой отметке внутренней
`review-time` шкалы.

### Проверка таймингов

Пользовательские таймкоды относятся к review-версии после вырезов, а
`video/review-timeline.tsv` хранит время исходника. Конвертация выполняется из
папки `video/`:

```bash
npm run time -- review-to-source 28:13
npm run time -- source-to-review 43:11
npm run time -- segment 18-question
```

Принятые review-интервалы фиксируются в `video/review-timing-locks.tsv` и
проверяются через `npm run check`. Для визуальной проверки четырёх границ
сегмента в полной композиции:

```bash
npm run render:timing -- 18-question
```

Монтажные вырезы хранятся только в `video/src/editorial-cuts.json`.

### Активный говорящий

Подсветка аватаров в полном review генерируется из
`episodes/841862-1payment/transcription.txt`. Скрипт нормализует исходные
speaker labels, применяет известные исправления диаризации и переводит
source-интервалы в review-шкалу через тот же `editorial-cuts.json`:

```bash
cd video
npm run speakers:generate
npm run speaker:at -- 32:21.05
```

Результат хранится в `video/src/generated/speaker-timeline.json` и проверяется
командой `npm run check`. Ручные исключения с причиной находятся в
`video/speaker-diarization.config.json`; сам generated-файл вручную не правится.

### Расшифровка и субтитры

Универсальный caption-pipeline принимает произвольную готовую аудиодорожку и
сохраняет каждый запуск в указанный каталог. Конкретные выпуски и пути в коде
не зафиксированы:

```bash
cd video
npm run captions:transcribe -- --input <audio-file> --output <run-directory>
```

Первый OpenAI-проход получает реплики и speaker labels, второй — таймкод каждого
слова. Из них создаются `words.json`, `utterances.review.json`, `captions.json`,
`captions.srt` и читаемая расшифровка. Словарь терминов и отображаемые имена говорящих можно
передать отдельными конфигурациями выпуска; скрипт не зависит от их названий и
расположения:

```bash
npm run captions:transcribe -- \
  --input <audio-file> \
  --output <run-directory> \
  --replacements <replacements.json> \
  --speakers <speakers.json>
```

После ручной правки `utterances.review.json` производные файлы пересобираются
без повторной транскрибации:

```bash
npm run captions:build -- --output <run-directory>
```

Общие безопасные настройки находятся в `video/.env`, а `OPENAI_API_KEY` —
только в игнорируемом `video/.env.local`.
